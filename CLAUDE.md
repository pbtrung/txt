# CLAUDE.md

This repo holds the txt document-storage system's design docs, a single-owner Cloudflare Worker/D1/R2/Access application, the browser UI, and the Python maintenance CLI.

## Design docs (read these before touching auth/storage code)

- `docs/auth.md` — Cloudflare Access owner authentication, the owner binding ticket, proof-of-possession (now required on every D1-mutating endpoint, not only R2 credential minting), and rate limiting.
- `docs/data_model.md` — the owner's D1 schema (`owner`, `key_store`, `catalog`, `documents`, `bookmarks`, `shares`), its per-row encryption model, and its optimistic-concurrency read/write model.
- `docs/storage_layout.md` — the R2 object-key layout documents, shared copies, and the catalog object live under.
- `docs/sharing.md` — public sharing, capability URLs, and presigned R2 reads.
- `docs/crypto.md` — the AEAD/HKDF/KEM primitives (Ascon-Keccak, HKDF-SHA3-512, ML-KEM-1024+X448) and the blob format used by `owner`/`key_store`/row-level D1 data and shared EPUB content alike, plus the separate native Web Crypto (AES-256-GCM/HKDF-SHA-256) scheme used only for the share grant envelope (the R2 object path, never content or key material).
- `docs/deployment.md` — the Worker, D1, R2, and Access configuration and release verification.

## Code layout

- `txt.py` — thin entry point; also runnable as the installed `txt` console script.
- `txt/` — one module per concern:
  - `creds.py` — loads the exact `OwnerCreds` file (Cloudflare account/D1/R2 credentials) and generates `user_root_key` when empty.
  - `logger.py` — `--verbose` progress logging.
  - `d1_client.py` — `D1Client`, a thin HTTP client for Cloudflare's D1 query API (`docs/data_model.md`), used directly by this batch tool rather than the Worker's ticket/proof-gated endpoints. D1's params array accepts only strings, so BLOB values are hex-encoded and paired with `unhex(?)` at the call site; a BLOB column read back from a `SELECT` arrives as a plain JSON array of byte values instead. Every request retries up to 3 times (1s/2s/4s backoff) on a connection error, a read timeout, or a 5xx response — D1's HTTP API has a real latency tail, and a long-running batch command issues many sequential calls in one run — but never on a 4xx, which retrying would only delay reporting.
  - `account_data.py` — `parse_owner_account()` validates and parses the owner's decrypted `encrypted_credentials` payload (`{user_handle, display_name, db_prefix}`) into an `OwnerAccount`.
  - `random_token.py` — base32-Crockford encoding, used for `db_prefix`/per-document key segments.
  - `leancrypto_wasm.py` — wasmtime binding to `sqlcipher/sqlcipher.wasm`'s bundled leancrypto build (AEAD, HKDF, KEM).
  - `crypto_blob.py` — docs/crypto.md's wrap/unwrap blob format, built on `leancrypto_wasm`.
  - `owner_init.py` — `OwnerInitializer`, the idempotent `--init-owner` implementation. It creates exactly one D1 `owner` row and validates existing owner material against `creds.owner_email`/`user_root_key`; the schema itself is Worker-managed (`wrangler d1 migrations`), not installed by this tool. Its `load_current_owner()` (read the singleton row, validate, decrypt) is the shared entry point `ingest.py` reuses to reach the owner's account and `umk`.
  - `r2_client.py` — `R2Client`, a thin boto3/S3-compatible wrapper for R2 (get/put objects, list objects with sizes, list keys, and delete key batches with partial-failure detection). Every client is configured with boto3's own "standard" retry mode (8 attempts) and a wider-than-default connection pool, so a transient connection-level failure (including a bad TLS record MAC, `botocore.exceptions.SSLError`) gets several chances to succeed before ever reaching this module's own code — a real failure a long-running batch command (`--ingest`, `--clean-bucket`) hit in practice.
  - `opf.py` — Calibre `.opf` sidecar detection and `<metadata>` parsing; `ingest.py` extracts just `title`/`authors`/`subjects`/`publisher` from it into each catalog entry (docs/data_model.md §2.1).
  - `catalog_writer.py` — `DocumentStore`/`CatalogWriter`, the generic D1+R2 write logic used by `ingest.py`: minting `key_store` rows, inserting a `documents`/`bookmarks` row (rolling its own `key_store` rows back if the insert fails), and merging/publishing the singleton R2-hosted catalog object. Takes already-read bytes/fields — no filesystem or source-format knowledge.
  - `ingest.py` — `TxtIngester`, the `--ingest` command: uploads each new EPUB in a directory as one R2 object and writes its `documents`/`key_store` rows directly to D1 via `catalog_writer.py`, then reconciles the R2-hosted catalog object. A local JSON checkpoint (`{db_prefix}.ingest-checkpoint.json` in `--local-db-dir`) records `{filename: document_id}` so a run interrupted between the D1 write and the catalog rewrite resumes cleanly; the catalog itself is also checked by filename first, so a lost checkpoint can't cause a silently-skipped catalog entry.
  - `bucket_cleaner.py` — `BucketCleaner`, the `--clean-bucket` command: deletes R2 objects not referenced by the D1 owner's `documents`/`catalog` rows, read from D1 a page of 1000 at a time via a `d.id > ?` keyset seek rather than one unbounded query or `OFFSET` (which would make D1 re-read and bill every already-returned row on each subsequent page). The entire `{db_prefix}/shared/` prefix is always retained regardless of any `shares` row's state, since the browser uploads a shared copy before registering it (`docs/sharing.md` §4) and this tool can't tell that race apart from an abandoned upload. Before deleting, it reports object count and total byte size per `docs/storage_layout.md` prefix (document/catalog/shared/other) plus a stale total.
  - `db_cleaner.py` — `DbCleaner`, the `--clean-db` command: retries a `shares` row stuck at `state = 'deleting'` (a prior revoke's R2 delete failed) — the only persisted stale state in the D1 design, since `worker/sharesEndpoint.ts` only ever inserts a row directly as `'active'`.
  - `db_updater.py` — `DbUpdater`, the `--update-db` command: a one-time data migration clearing `documents.access_key_id`/`access_blob` back to `NULL` for documents ingested before those columns became nullable (`worker/migrations/0002_nullable_access.sql`) — a single D1 `UPDATE`, since `trg_documents_clear_access_key` deletes each now-orphaned `key_store` row automatically. Not a schema-installing command; schema changes stay Worker-managed (`wrangler d1 migrations`).
  - `catalog_checker.py` — `CatalogChecker`, the `--check-catalog` command: a read-only diagnostic reporting any drift between the D1 owner's `documents` rows and the R2-hosted catalog object (`docs/data_model.md` §2.1) — documents missing from the catalog (invisible in the Library screen until `--ingest` reconciles them) and catalog entries referencing a `document_id` that doesn't exist (shouldn't happen; nothing in this design deletes a document). Never writes to D1 or R2.
  - `replace_images.py` — `--replace-images`: replaces EPUB images with placeholders and constrains their display size; unrelated to the rest of this package's account/storage logic.
  - `edit_epub.py` — `--edit-epub`: splits EPUB spine items into soft 1.2 MB parts, rewrites title/series metadata and sidecars, then applies the same image replacement rules as `--replace-images`.
  - `cli.py` — the click entry point; wires only the commands above that currently work against the D1 design.
- `txt/tests/` — pytest. Crypto tests run against the real wasm engine (`txt/tests/conftest.py`'s session-scoped `engine` fixture); everything else fakes only the network boundary (D1, R2) — never the crypto itself.
- `sqlcipher/` — the prebuilt SQLCipher+leancrypto wasm module. Not built from source in this repo. Loaded by both sides independently: `leancrypto_wasm.py` (wasmtime) server/tooling-side, and `ui/src/crypto/sqlcipherLoader.ts` (browser, SRI-checked) client-side — neither opens it as an actual SQLCipher database; both use it only for its bundled leancrypto AEAD/HKDF/KEM primitives.
- `creds/` — local, gitignored credential files. Never commit these. Never run a command against a real one yourself — hand it to the user to run.
- `ui/src/main.tsx` — entry point: global CSS/font imports, `monitoring.ts`'s Sentry init, then mounts `<App>`.
- `ui/src/App.tsx` — top-level routes: `/` (Unlock), `/shared` (public reader, no auth), `/library` and `/read/:txtId` (gated behind `VaultContext`'s unlocked status), everything else redirects to `/`.
- `ui/src/state/VaultContext.tsx` — the one in-memory owner session (`VaultSession`): unlock-file parsing, `GET /v1/owner`, key unwrapping, the `R2Session`, and the `LibraryStore` instance all live here for the page's lifetime only, never persisted — a reload always lands back on Unlock (`docs/auth.md` §5).
- `ui/src/env.ts` — `isBrowser()`, used by `crypto/sqlcipherLoader.ts` to tell a real browser apart from Vitest's jsdom environment, which never executes an injected `<script>` tag.
- `ui/src/monitoring.ts` — Sentry init; redacts URLs (which can carry a share capability/content key, `docs/deployment.md` §5) from every event before it's sent, and is a no-op unless `VITE_SENTRY_DSN` is configured.
- `ui/src/index.css`, `ui/src/tailwind.css`, `ui/src/theme.scss` — global styles: the Tailwind/daisyUI entry point, the Skypiea color theme, and hand-written overrides/utility classes Tailwind alone can't express.
- `ui/src/setupTests.ts`, `ui/src/vite-env.d.ts` — Vitest global test setup and Vite's own ambient type declarations.
- `ui/src/components/` — generic, cross-screen UI: `AppErrorBoundary.tsx` (top-level crash boundary; console-logs only in dev — everything else in this app routes through `monitoring.ts`'s redaction first, and this boundary also wraps the public shared-reader page, where a raw stack could leak the URL fragment); `DrawerPanel.tsx` (the slide-in panel `TocPanel`/`ReaderInfoPanel` both use); `IconButton.tsx` (icon-only button with a tooltip); `ScreenMessage.tsx` (loading/error states with a step progress indicator).
- `ui/src/crypto/` — the browser's half of `docs/crypto.md`'s Blob Format, built on the same `sqlcipher/sqlcipher.wasm` leancrypto build `txt/leancrypto_wasm.py` uses server-side: `sqlcipherLoader.ts` loads the wasm module in-browser (SRI-checked at load time against a hash `ui/vite.config.ts` bakes in at build time); `aead.ts` wraps its raw HKDF-SHA3-512/Ascon-Keccak exports, mirroring `leancrypto_wasm.py`'s own call shapes 1:1; `cryptoBlob.ts` ports `txt/crypto_blob.py`'s Encrypt/Decrypt exactly; `brotli.ts` (via `brotli-wasm`, not `CompressionStream`, for one WASM implementation shared with Node/Vitest, since browser "br" support isn't universal) compresses/decompresses the structured payloads that format wraps.
- `ui/src/data/apiClient.ts` — the browser's REST client for `/v1/*`: same-origin `fetch()` (Cloudflare Access supplies the session cookie), owner-proof headers on every mutating call, and Access-challenge detection (`AccessRequiredError`). `ownerProof.ts` builds and signs the canonical proof bytes; `session.ts` unwraps the owner's keys from `GET /v1/owner`'s response; `libraryStore.ts` fetches and decrypts documents/catalog/bookmarks and holds the reactive session-lifetime state — there is no local database file; `r2.ts`/`r2Session.ts` hold the two scoped, refreshing R2 credentials; `shares.ts`/`sharedReader.ts` implement the owner and recipient sides of public sharing; `readingState.ts` is the reading-position timing state machine (grace period, debounced/throttled saves) that decides when `libraryStore.ts` persists; `epubRenderer.ts` wraps `@likecoin/epub-ts`'s `Book`/`Rendition` behind a mockable class, the same pattern `r2_client.py` uses for boto3; `creds.ts` parses the browser's own unlock-file shape (`docs/auth.md` §3/§5 — just `user_root_key`); `epubOpf.ts`/`opfMetadata.ts` parse an EPUB's own internal package document once its bytes are in hand, mirroring `txt/opf.py` field-by-field, since the catalog only keeps a fixed metadata subset (`docs/data_model.md` §2.1); `readerDocument.ts` fetches and decrypts one document's EPUB bytes by its own `content_key` (`docs/storage_layout.md`), combining catalog identity with what the EPUB's own OPF carries; `loadCoalescer.ts` is the shared "join an in-flight load, broadcast its progress" logic `useReaderDocument.ts`/`useSharedReaderDocument.ts` both need; `networkRequest.ts` is the timeout-plus-bounded-retry wrapper every `fetch()`-based call goes through; `readerTheme.ts` is the reader's fixed typography, injected into each EPUB section's own iframe via `Rendition.themes` (a plain CSS import can't cross into a child iframe document); `sanitizeHtml.ts` is the DOMPurify wrapper for an EPUB's own `dc:description` — untrusted HTML from a book file, rendered directly into this app's own page rather than sandboxed the way the book's own content is via epub.js.
- `ui/src/screens/Library/` — the post-unlock home screen: `LibraryScreen.tsx` is the shell, owning only search/navigation state; `LibraryContent.tsx`, `LibraryHeader.tsx`, `LibrarySidebar.tsx`, `LibraryMenu.tsx` render its panes; `BookList.tsx` is the shared book-row rendering used by every list (an explicit `"none" | "access" | "bookmark"` badge mode per list, never inferred from a row's own data, so a book's badge never leaks into a list it doesn't belong in); `libraryModel.ts` is pure search/sort/browse logic (Fuse.js) over an already-loaded book list; `libraryView.ts` holds the view-routing types/helpers between sidebar sections; `useLibraryBooks.ts`/`useShares.ts` are the session-selector hooks reading `VaultContext`'s already-loaded `LibraryStore`/shares list.
- `ui/src/screens/Reader/` — the EPUB reading screen and its public counterpart: `ReaderScreen.tsx` is the owner shell (document loading, panel visibility); `SharedReaderScreen.tsx` is the analogous shell for `/shared`; `ReadyReaderView.tsx`, `ReaderToolbar.tsx`, `ReaderNavigation.tsx`, `ReaderInfoPanel.tsx`, `TocPanel.tsx`, `BookmarkRow.tsx` render their panes and panels; `useEpubRenderer.ts` mounts `epubRenderer.ts`'s `Book`/`Rendition` wrapper; `useReaderDocument.ts`/`useSharedReaderDocument.ts` are the owner/recipient document-loading hooks (via `loadCoalescer.ts`); `useReadingState.ts`/`useSharedReadingState.ts` are the owner (server-persisted via `readingState.ts`) and recipient (`localStorage`-persisted, capability-keyed, `docs/sharing.md` §5) reading-position/bookmark state machines.
- `ui/src/screens/Unlock/UnlockScreen.tsx` — the pre-session screen: one button that loads the owner's unlock file (`creds.ts`'s shape) and hands it to `VaultContext`.
- `ui/src/util/` — dependency-free helpers shared across the above: `base64.ts`/`base32Crockford.ts` (the latter porting `txt/random_token.py`'s encoding exactly, for the `db_prefix`/R2 path segments the browser itself generates); `bookmarkMatch.ts` (the one CFI-lookup both reading-state hooks share); `classNames.ts`; `errorMessage.ts`; `validation.ts` (parsing untrusted JSON shapes — API responses, the unlock file — into typed values).
- `ui/tests/` — vitest, mirroring the UI source tree rather than living beside source files.
- `worker/` — the Cloudflare Worker serving `/v1/*` and `dist/`: `index.ts` splits every request between `/v1/*` and the static assets binding; `api.ts` is the `/v1/*` route table itself, gating each route behind the verified Access JWT (`docs/auth.md` §1/§2) and dispatching to its handler, with a `requiresProof`/`public` flag per route deciding which need proof of possession; `access.ts` verifies the Cloudflare Access JWT; `ownerTicket.ts`/`ownerProof.ts` issue and verify the owner binding ticket and its proof-of-possession signature (`docs/auth.md`); `requireProof.ts` is the shared per-endpoint gate mapping a proof failure to its documented status code; `requireVar.ts` reads a configured secret/var and refuses to run against an unsubstituted placeholder; `env.d.ts` ambient-merges the Worker's own secrets (`TICKET_SIGNING_KEY`, `R2_PARENT_ACCESS_KEY_ID`, `R2_PARENT_SECRET_ACCESS_KEY`, `SHARE_GRANT_KEY`) into the generated `Env`/`Cloudflare.Env` types, since `wrangler types` only sees `wrangler.jsonc`'s `vars`, never a `wrangler secret`-set value; `ownerEndpoint.ts`, `documentsEndpoint.ts`, `bookmarksEndpoint.ts`, `catalogEndpoint.ts` implement the owner's D1-backed endpoints (`docs/data_model.md`); `r2CredentialsEndpoint.ts` mints the browser's two scoped, short-lived R2 credentials by locally signing a JWT, with no network call (`docs/storage_layout.md`); `sharesEndpoint.ts`, `sharedUrlEndpoint.ts`, `shareGrant.ts`, `shareValidation.ts` implement public sharing — creation/revocation, anonymous redemption, the AES-256-GCM grant envelope, and share-path validation (`docs/sharing.md`); `base64.ts` holds shared encoding/hashing helpers; `migrations/` holds the D1 schema (`wrangler d1 migrations`, `docs/data_model.md` §2). `worker/tests/` mirrors this list, exercising every endpoint through the real Workers runtime (`@cloudflare/vitest-pool-workers`) rather than mocking `fetch()` handling.
- `wrangler.jsonc`, `package.json`, `scripts/deploy.sh` — the Worker's deployment config: one Worker serving `/v1/*` and `dist/` together, with D1 and R2 bindings. `scripts/deploy.sh` resolves or creates the production D1 database and R2 bucket by name, applies pending D1 migrations, then deploys (`docs/deployment.md`).
- `ui/_headers` — response headers copied into `dist/` by `npm run ui:build`.

## Conventions

- Functions stay ≤15 lines; use a class (not free functions) for anything holding state — a client, an engine, a session.
- Reuse the existing generic pieces (`D1Client`, `CryptoBlob`, `OwnerInitializer`, `R2Client`) instead of duplicating HTTP, crypto, or storage logic in a new command.
- UI TypeScript is formatted with Prettier at 88 columns (`.prettierrc.json`); run `npm run format` before committing UI changes. `.prettierignore` excludes generated/vendored files and the Python tree.
- The Python tree is linted and formatted with ruff (`[tool.ruff]` in `pyproject.toml`, 88 columns to match the TS side): `python3 -m ruff check .` and `python3 -m ruff format .` before committing.
- `ui/` is linted with ESLint (`eslint.config.js`): `npm run lint` before committing UI changes.
- The project's own TypeScript is 7.x (`typescript7`, aliased since typescript-eslint doesn't support TS 7 yet); a plain `typescript@6.0.3` devDependency exists solely to satisfy typescript-eslint's own peer range. `npm run tsc` (used by every `*:typecheck`/`ui:build` script) always resolves to the real 7.x compiler, never the 6.x one — the alias exists only so both can coexist under `node_modules` without conflict.
- Docs (this file, README, docs/*) describe current behavior and supported migration inputs only — no commit hashes or narrated development history.
