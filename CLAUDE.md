# CLAUDE.md

Guidance for Claude Code (or any agent) working in this repository.

## What this is

A personal document-storage system. One administrator account plus any number of ordinary user accounts, each with its own pair of databases: **AA**, a per-account Turso Cloud (libSQL) database holding a page map, version history, snapshot pins, bundle/library-index pointers, and — inline, as blobs — the SQLCipher ciphertext of every page version; and **BB**, the SQLCipher-keyed SQLite database the application actually opens and issues SQL against, whose pages live nowhere but AA (no local file, no R2/S3 object per page). Document part payloads, bundles, and the library index are the three things that still live as R2/S3 objects, each under its own `{db_prefix}/{t,b,i}/...` prefix. Every sensitive value AA holds is stored wrapped, never as plaintext: `umk` is wrapped by `user_root_key` (which never leaves the client); `db_prefix`, `object_key`, `lib_idx_key`, and `bundle_enc_key` are wrapped directly by `umk`; `bundle_key` (the bundle's own R2 address) is wrapped by that row's own `bundle_enc_key`, one level removed from `umk` rather than wrapped by it directly. Only a client that can unwrap `umk` can reconstruct an actual R2/S3 address or open BB. Read `docs/data_model.md`, `docs/auth.md`, and `docs/crypto.md` before making any design-level change — they're the source of truth, not this file.

The account model: `ctl`, an ordinary Turso database in the same organization, maps a Firebase uid to that account's own `db_path` and `type` (`admin` or `user`). Only the administrator account can mint Turso database tokens and create new Turso databases (via the Platform API token in its own creds.json); this repo has no code path that provisions an ordinary user's account end to end — that's `--init-admin`'s creds.json reused with a different uid's row already present in `ctl`.

## Commands

```
python3 txt.py --init-admin <creds.json> [-v|--verbose]
python3 txt.py --init-db <creds.json> [-v|--verbose]
python3 txt.py --replace-images <src_dir> <dst_dir> [-v|--verbose]
python3 txt.py --ingest <dir> --creds <creds.json> [-v|--verbose]
python3 txt.py --collect-garbage --creds <creds.json> [-v|--verbose]
```

Entry point is `txt.py` → `txt/cli.py`'s `cli()` → one of `AdminInitializer` (`admin_init.py`), `DbInitializer` (`init_db.py`), `ImageReplacer` (`replace_images.py`), `TxtIngester` (`ingest.py`), or `GarbageCollector` (`gc.py`). All but `--replace-images` take the same creds.json shape (`Creds` in `creds.py`); `--replace-images` needs no creds at all.

## Architecture map

- `txt/creds.py` — `Creds` dataclass and `load_creds`/`ensure_user_root_key`. Required fields: `turso_org_token`, `turso_ctl_db_url`, `turso_group`, `turso_org`, `firebase_email`, `firebase_password`, `firebase_api_key`. Optional: `display_name`, `user_root_key` — `ensure_user_root_key` fills in a fresh 256-random-byte, base64 value only when empty, writing it back into the source creds.json while preserving every other field, and never overwriting an existing value — and `r2_config` (an `R2Config`: `endpoint`, `read_only`/`read_write` access key id + secret, `region`, `bucket`), required only by `--ingest`.
- `txt/firebase_auth.py` — `FirebaseAuth.sign_in`: plain REST call to `identitytoolkit.googleapis.com`'s `accounts:signInWithPassword`, returns the Firebase uid (`localId`).
- `txt/turso_api.py` — `TursoClient`: the Turso Platform API (`create_database`, `mint_db_token`). `extract_db_name(url, account_name)` recovers a database's own name from its `libsql://{name}-{account_name}.../` URL by locating the `-{account_name}.` marker — not by naive splitting, since a name could itself contain a hyphen.
- `txt/libsql_client.py` — `LibsqlClient`: the libSQL/Turso HTTP `/v2/pipeline` API (`execute`, `query`). BLOB arguments and result cells are `{"type": "blob", "base64": ...}`, never raw bytes as `"text"` — confirmed against Turso's own HTTP API reference, not guessed.
- `txt/random_token.py` — `generate_db_path`/`generate_random_prefix` (an alias, same recipe): 32 random bytes rendered as 52 lowercase base32-Crockford characters, used for `ctl.db_path`, `meta.db_prefix`, and `txt.prefix`.
- `sqlcipher/` — a vendored, custom-built `sqlcipher.wasm` (plus its Emscripten JS glue, a `.symbols` export list, and Node test scripts) that statically links leancrypto and configures SQLCipher to use leancrypto's Ascon-Keccak cipher (`PRAGMA cipher == 'ascon-keccak-512'`, confirmed via `test-roundtrip.mjs`). Not built in this repo — treat as a build artifact, tracked in git since there's no build step here to regenerate it. `sqlcipher.js.symbols` is the authoritative list of exported functions when the minified `sqlcipher.js` itself isn't worth reading directly.
- `txt/leancrypto_wasm.py` — `LeancryptoEngine`: hosts `sqlcipher.wasm` directly via `wasmtime`, with no Node/JS glue involved at all. `wasmtime`'s built-in WASI covers the `wasi_snapshot_preview1` imports; Python stubs cover the `env.*` Emscripten imports (filesystem syscalls, date/timezone math, signals) that this crypto-only usage never actually reaches. Wraps `lc_wasm_hkdf_sha3_512`/`lc_wasm_aead_encrypt`/`lc_wasm_aead_decrypt` (Ascon-Keccak AEAD, 64-byte key/nonce/tag) and `lc_kyber_1024_x448_keypair`/`_enc`/`_dec` (the composite ML-KEM-1024 + X448 KEM, `docs/crypto.md`'s Composite KEM Key Sizes) through malloc'd wasm-memory buffers.
- `txt/crypto_blob.py` — `CryptoBlob`: `docs/crypto.md`'s Encrypt/Decrypt blob format (`magic(2) || version(2) || salt(64) || ciphertext || tag(64)`, AD = `magic||version||salt` since `context` isn't implemented yet) on top of `LeancryptoEngine`, plus `encrypt_json`/`decrypt_json` (brotli-compress the JSON payload first).
- `txt/admin_init.py` — `AdminInitializer`: signs into Firebase, ensures `ctl.users` exists, generates a `db_path` and creates that Turso database, inserts the `ctl.users` row (`type = 'admin'`) — idempotent: an existing row for this uid is reported, not recreated.
- `txt/account_session.py` — `AccountSession`, extracted out of `DbInitializer` and reused by `TxtIngester`: `connect()` (sign in → look up `ctl` → connect AA, lazily creating/minting a token on a 404 rather than checking a NULL first), `read_umk`/`read_db_master_key` (unwrap `key_store`/`cred_store` given `umk`'s IKM), plus the shared `cred_store_rows` helper.
- `txt/init_db.py` — `DbInitializer`: looks up this uid's `db_path`/`type` in `ctl` (via `AccountSession`), ensures the AA schema (including `bundles`/`library_index`'s table shapes, though `--init-db` never inserts rows into either — only `--ingest` does), establishes `umk` (via `key_store`, every account has one), wraps a freshly generated `db_prefix` under `umk` into `meta`, and wraps `{display_name, db_master_key}` under `umk` into `cred_store`. Every step is check-then-insert — idempotent, safe to rerun.
- `txt/opf.py` — `find_opf_sidecar`/`parse_opf_metadata`: locates a `<name>.opf` sibling for a `<name>.epub` file and flattens its `<metadata>` into a dict (`dc:*` elements, `<meta name=.. content=..>` pairs, repeated tags collapse to a list, Calibre's own bookkeeping identifiers/contributor dropped). `calibre:title_sort`, when present, is what `library_index.py` uses for `doc.sort_key`.
- `txt/replace_images.py` — `ImageReplacer(src_dir, dst_dir, logger).run()`: for every `*.epub` in `src_dir`, rewrites `<img>` tags (constrains dimensions, strips corrupted captions) into `dst_dir`, then copies every `*.opf` verbatim. The per-file zip-rewriting helpers are ported verbatim from an external script and deliberately left unrefactored.
- `txt/r2_client.py` — `R2Client`: a thin `boto3` S3-compatible client against R2, built from `r2_config`'s read-write credentials; `put_object(key, body)` only (no read path exists in this repo yet).
- `txt/bb_engine.py` — `register_js_vfs`/`BBEngine(LeancryptoEngine)`: a from-scratch Python port of `sqlcipher/js-vfs.mjs`'s in-memory VFS, using `wasmtime.Table.grow`/`.set` on `__indirect_function_table` in place of Emscripten's `Module.addFunction`. `BBEngine` opens a real, writable BB (`open`, `exec_sql`/`execute`/`query`, `last_insert_rowid`, `page_count`), tracks every dirtied page as `{page_no: bytes}` (`drain_dirty_pages`), and can preload existing page bytes before opening (`load_pages`) to resume a BB that already has AA-committed pages.
- `txt/ingest.py` — `TxtIngester`, the `--ingest DIR --creds CREDS_JSON` implementation: opens BB (loading its existing pages from AA if any), skips any `*.epub` whose filename already matches a `txt.name` row, and for each remaining file — splits it into 49999–99999-byte parts (docs/data_model.md §7), encrypts each under a fresh per-document `txt.txt_key`, uploads all parts to R2 in parallel (≤20 workers, encryption itself stays sequential — see constraints below), and only on full success writes `txt`/`txt_meta`/`txt_parts` rows to BB and flushes BB's dirty pages to AA (`versions`/`page_versions`/`meta.head_version`, chunked to ≤20 `page_versions` rows per HTTP batch). After all files, rebuilds the bundle and library index (`_rebuild_derived_artifacts`) if either is stale; a rebuild failure is logged and retried next run, never fatal.
- `txt/bundle.py` — `BundleBuilder`: assembles the header/page-map/hot-pages/index bundle format (docs/data_model.md §6.3) and encrypts it under a fresh `bundle_enc_key`. Takes the hot-page selection as a plain `hot_page_nos` argument — it does no `dbstat` querying itself, so it's unit-testable with a bare dict — the scan itself lives in `TxtIngester._scan_hot_page_nos` (`ingest.py`), since that's the one place holding an open, keyed BB connection.
- `txt/gc.py` — `GarbageCollector`, the `--collect-garbage --creds CREDS_JSON` implementation (docs/data_model.md §6.4): expires stale `snapshots`, deletes superseded `page_versions` rows past `gc_horizon`, deletes every retired bundle's row and R2 object (no grace window — this CLI has no reader that could be mid-download), and sweeps orphaned objects under `b/`, `i/`, and `t/` (the last needs BB open read-only, to read live `txt.prefix` values). Every AA SELECT/DELETE is capped and looped via `GC_BATCH_SIZE`, matching `MAX_PAGES_PER_BATCH`'s reasoning in `ingest.py`.
- `txt/library_index.py` — `LibraryIndexBuilder`: projects BB's `txt`/`txt_meta` into the stdlib-`sqlite3` file described in docs/data_model.md §8.1 (`doc`/`term`/`doc_term`/`built`), `VACUUM`s and `serialize()`s it, brotli-compresses, and encrypts under `lib_idx_key`.
- `txt/logger.py` — `Logger`: timestamped `verbose`/`info` lines, `verbose` gated on `--verbose`.
- `txt/cli.py` — click-based CLI wiring `--init-admin`/`--init-db`/`--replace-images`/`--ingest`/`--creds`/`--verbose`. `_run_ingest` owns `ingester.bb.close()` in a `try/finally` around `TxtIngester.run()` rather than `run()` closing it itself, so tests can inspect `ingester.bb` after `run()` returns.
- `txt/tests/` — the pytest suite (below).

## Non-obvious constraints (confirmed empirically — don't re-derive, don't assume otherwise)

- **Hosting `sqlcipher.wasm` directly with `wasmtime` needs two explicit calls Emscripten's own JS runtime normally makes for you**: `__wasm_call_ctors` (static constructors) and `lc_activate_library` (leancrypto's own activation/self-test gate). Skip either and every leancrypto call fails as if the library were never activated — confirmed the hard way (`lc_wasm_aead_encrypt` returning a nonzero rc with otherwise-correct arguments).
- **`lc_seeded_rng` is `extern struct lc_rng_ctx *lc_seeded_rng`** — the wasm module exports it as an immutable `Global` holding the *address* of that pointer variable, not the pointer's current value. Using the KEM keypair functions needs one more dereference: read 4 bytes at that address to get the actual `rng_ctx` pointer to pass in.
- **The `lc_wasm_aead_encrypt`/`lc_wasm_aead_decrypt`/`lc_wasm_hkdf_sha3_512` wrapper functions have no type metadata in the compiled wasm/JS** (11 and 8 raw `i32` params respectively) — their real argument order came from reading `sqlcipher/test-roundtrip.mjs`'s own calls against them, not from guessing a leancrypto-API-conventional order.
- **Turso/libSQL's HTTP pipeline API represents BLOB values as `{"type": "blob", "base64": ...}`**, both as request arguments and in query result cells — not raw bytes under `"value"` the way `text`/`integer` cells work. **Its own base64 result cells come back without trailing `=` padding** — confirmed against real infra, not the docs — so `_cell_value` pads to a multiple of 4 before calling `base64.b64decode`, which otherwise raises `binascii.Error: Incorrect padding`. **`"integer"`-typed cells' `value` is itself a decimal *string*** (Hrana's own precision-preserving convention for 64-bit ints in JSON, where a plain JSON number would lose precision) — `_cell_value` converts it with `int()` rather than returning it as-is, which every AA `INTEGER` column (`head_version`, `built_at_version`, `page_no`, ...) depends on for arithmetic/comparisons downstream. Both quirks only surface against real Turso: the fakes across `txt/tests/` bypass the wire format entirely and hand back native Python values directly, so neither was caught until a real `--ingest` run hit it.
- **`PRAGMA page_size` only takes effect on an empty database** — `DbInitializer` sets AA's own page size (32768, matching BB's SQLCipher page size) before any `CREATE TABLE`, since `page_versions.data` holds a full ~32 KiB BB page per row and AA's 4096-byte default would otherwise fragment every such row across roughly eight overflow pages.
- **`umk` is always 128 random bytes, generated once and persisted wrapped by `user_root_key`, never re-derived** — every account (admin or not) has a `key_store` row for exactly this reason; only an admin's `key_store` row also carries the composite KEM keypair (currently unused, kept for a future feature per `docs/crypto.md`).
- **`db_prefix`/`object_key`/`lib_idx_key`/`bundle_enc_key` are `BLOB`, wrapped under `umk`; `bundle_key` is `BLOB`, wrapped under that row's own `bundle_enc_key`** — AA never holds a directly readable R2/S3 address for any object population, and a bundle's address is only reachable by first unwrapping that bundle's own key, not `umk` alone.
- **This project's Python code follows a `<=15 lines per function`, class-based-reuse convention** — matches the style already in `txt/`; keep new code consistent with it (see `LeancryptoEngine`'s `_call`/`_free_all`/`_write`/`_read` helpers for the pattern of factoring out repeated malloc/free/error-check boilerplate).
- **`wasmtime`'s `Store` is not safe to call concurrently from multiple threads** — a real, empirically-confirmed native crash. `TxtIngester._upload_parts` encrypts every part sequentially *before* spawning any thread; only the R2 `put_object` calls (boto3, thread-safe) run inside the `ThreadPoolExecutor`.
- **The vendored `sqlcipher.wasm` build compiles in `SQLITE_ENABLE_DBSTAT_VTAB` and `SQLITE_ENABLE_DBPAGE_VTAB`** — both are ordinary SQL virtual tables (`dbstat`, `sqlite_dbpage`), so they work through `BBEngine.query()` with zero VFS/wasm-binding changes. `TxtIngester._scan_hot_page_nos` uses `dbstat` (grouped by `name`, `pagetype = 'internal'` = interior page, whole small groups carried whole, threshold ≤64 pages — not a value docs/data_model.md mandates, just a judgment call) for real hot-page selection. **`sqlite_dbpage.data` is decrypted plaintext**, not the SQLCipher ciphertext AA/bundles need — SQLCipher's codec sits below the pager, so anything reading through it (b-tree cursors, `dbstat`, `sqlite_dbpage`) sees plaintext; hot-page bytes for a bundle still have to come from `page_versions.data` in AA, never from `sqlite_dbpage` directly.
- **`bundle_enc_key` is minted fresh per bundle and never reused across rebuilds; `lib_idx_key`/`object_key` are minted once and reused on every rebuild** — a bundle is a brand-new R2 object every time (the old one is retired, not overwritten, since a range-read into an overwritten key could straddle two generations); the library index is fetched as one whole-object GET, so overwrite-in-place is safe and its key/address stay fixed.
- **Document parts are 49999–99999 bytes**: `n = ceil(size/99999)` parts of `ceil(size/n)` bytes each, never brotli-compressed (an EPUB is already a ZIP) — see `txt/ingest.py`'s `split_parts`.
- **`--ingest` is resumable at the txt_id (filename) level, not the part level**: a file's parts are all encrypted and uploaded to R2 before any BB row is written for it, so a mid-upload failure leaves no partial `txt`/`txt_parts` rows — the next run just re-attempts that filename from scratch. BB's dirty pages are only flushed to AA after a file's rows are written, chunked to ≤20 `page_versions` rows per AA batch (Hrana can time out on larger ones).
- **A reassembled BB needs every dirtied page, not just page 1** — SQLite's own page-1 header records the database's total page count, so opening BB against a reloaded page set that's missing a page (e.g. the root page a `CREATE TABLE` allocated alongside page 1) fails with `rc=11 "database disk image is malformed"`, not a decrypt error. `GarbageCollector`/`TxtIngester` always load every live row from `page_versions`, never a partial set; test fixtures that hand-build a BB state must do the same (`txt/tests/test_gc.py`'s `_real_pages` captures `dict(bb.dirty_pages)` in full).
- **GC batches every AA round trip, both reads and writes** — `page_versions`/`snapshots` cleanup loops `SELECT ... LIMIT GC_BATCH_SIZE` followed by a batched `DELETE` per page, rather than one unbounded SELECT or DELETE; a long-uncollected backlog could otherwise return or match far more rows than one Hrana request should carry. Bundle/library-index/part orphan sweeps skip this — `bundles` is naturally tiny (rebuilt only on a 25%-page-change threshold) and the R2-side `list_keys`/`delete_keys` already paginate/chunk against S3's own limits, unrelated to Turso.

## Verification

`txt/tests/` is a real pytest suite (`pytest txt/tests/`, or `pip install -e ".[dev]"` first). Follows this project's real-building-blocks philosophy: `test_leancrypto_wasm.py` and `test_crypto_blob.py` run against the actual `wasmtime`-hosted leancrypto engine (real AEAD round-trip and tamper-detection checks against ciphertext/aad/tag/wrong-key, a real KEM encapsulate/decapsulate agreement check, real HKDF determinism) rather than mocking the crypto layer; `test_bb_engine.py` drives a real `BBEngine` through open/write/reassemble-pages/reopen round trips, including a wrong-key rejection; `test_bundle.py`/`test_library_index.py` build real bundles/library-index files and decrypt+parse them back; `test_init_db.py`/`test_account_session.py`/`test_ingest.py`/`test_gc.py` verify idempotency, resumability, and gating (a failed part upload leaves no BB row or AA flush; superseded pages/retired bundles/orphans get deleted, live state never does) against fake Firebase/Turso/libsql/R2 clients — `test_ingest.py`'s `FakeAaState` and `test_gc.py`'s state dict are genuinely stateful (not just a call recorder), since resumability and deletion correctness both depend on a client instance seeing the effect of its own prior statements — using the real crypto engine (and, in `test_gc.py`, a real `BBEngine` for its `t/` orphan sweep) underneath so wrapped values in test assertions are genuine blobs, not stand-ins. `test_opf.py`/`test_replace_images.py`/`test_r2_client.py` round out the ingest pipeline's own pieces.

Not verified by this suite, and not run against real infra by the agent itself (hand real creds.json files to the user instead): the actual Turso Platform API / libSQL HTTP calls, Firebase sign-in against a real project, and real R2 uploads.

## Commit conventions

Detailed commit messages (imperative subject, bullet-point body explaining what and why), **no AI/Claude attribution ever** (no `🤖 Generated with Claude Code`, no `Co-Authored-By: Claude`), always push after committing. A `/commit` skill (`.claude/commands/commit.md`) automates this.

## Secrets

`.gitignore` blocks all `*.json` (creds.json files carry real Firebase/Turso secrets) and the whole `creds/` directory. Never commit a JSON file containing real credentials; double-check contents before `git add` on anything JSON-shaped.
