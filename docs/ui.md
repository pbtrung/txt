# Web UI — visual design

Implemented in `ui/` (React + TypeScript + Vite). This describes the visual design for the local web reader: three screens — Unlock, Library, Reader — built on Bootstrap (both CSS and its icon set). It covers layout and appearance only; see [docs/data_model.md](data_model.md)/[docs/credentials.md](credentials.md) for the underlying schema and credential model this UI reads from.

## Look and feel

Mostly stock Bootstrap: default components (`navbar`, `list-group`, `progress`, `input-group`, `badge`, `btn`), default system-font stack (except the Reader's reading column, see Screen 3), default light/dark theming. The one deliberate brand touch is the primary accent — a brass/gold tone (lighter and more saturated in dark mode, darker and more muted in light mode) — set via Bootstrap's own theme-color variables so every component that already references the primary color (buttons, progress bars, links, the active nav item) picks it up automatically, in both themes, with no per-component overrides needed.

No cover art anywhere — the vault only ever holds text, so titles and author names carry the visual weight instead of a thumbnail grid.

The browser tab's favicon (`ui/leancrypto/favicon.svg` — that directory is Vite's `publicDir`, see `vite.config.ts`) reuses Bootstrap Icons' `book` glyph, the same one in the wordmark, recolored to the brass/gold accent.

The Library and Reader shells are full width through `lg`, then capped to 60% (and centered) at `lg` and above — full-bleed matters more on a narrow screen than reading-width comfort, but a wide monitor shouldn't stretch either screen edge-to-edge.

Every icon-only bordered button across the app (Library's nav drawer toggle and Lock, Reader's Info/Bookmarks toggles) shares one visual language: a brass-bordered outline button with a brass icon when idle. The two that toggle a dropdown (Library's nav drawer, Reader's Info and Bookmarks) additionally fill solid brass when open, with the icon switching to plain white to stay legible against that fill — the same open/closed cue everywhere a dropdown can be toggled. Reader's Previous/Next are the one exception: brass icons with no button border at all, unlike every other icon button in the app. Text inputs and selects share the same brass theming instead of Bootstrap's default gray/blue — Library's search field, Reader's font-size dropdown and part-number box — the same full-strength border as a bordered button at rest, that switches to an even brighter brass accent (border and glow alike) on focus, in place of the stock blue browsers default to.

## Screen 1 — Unlock

The only job here is loading the credential file. No headline, no explanatory copy, no dropzone preview — a wordmark and a single button.

```
┌────────────────────────────────────────────────┐
│                                                │
│                                                │
│               [library]  Skypiea               │
│                                                │
│            ┌──────────────────────┐            │
│            │ [file]  Choose File  │            │
│            │         to unlock    │            │
│            │         your library │            │
│            └──────────────────────┘            │
│                                                │
│                                                │
└────────────────────────────────────────────────┘
```

- Centered column, vertically and horizontally, independent of screen size.
- The button carries both the action ("Choose File") and its effect ("to unlock your library") as a two-line label, so no separate sentence of instruction is needed above it.
- While unlocking, a small spinner and two lines appear under the button, both updating live as unlock() moves through its phases ("Signing you in" → "Unwrapping your keys" → "Loading your books" → "Loading your read progress" → "Loading your bookmarks" — the three requests behind the Library screen's data are each their own phase, not folded into one generic "Loading your library" step): a "Step N of 5" counter on top, the current phase's label beneath it. Before the first phase lands (or once it's already finished), the counter line holds its place with a non-breaking space rather than popping in/out, and the label falls back to a generic "Setting up your library…". The Library screen isn't shown until the vault is fully ready (metadata, read positions, and bookmarks all loaded), not just as soon as the password checks out.

## Screen 2 — Library

Two panes: a catalog nav on the left, a plain list of books on the right — no card grid, no cover thumbnails or monogram tiles.

```
┌────────────────────────────────────────────────────────────────────┐
│   [lib] Skypiea       [search  Search your library]                │
├────────────────┬───────────────────────────────────────────────────┤
│ ● Recent    2  │ Recent                            2 in progress   │
│ All books  10  │───────────────────────────────────────────────────│
│                │ CONTINUE READING                                  │
│ BROWSE         │───────────────────────────────────────────────────│
│ Authors     9  │ 21 Lessons for the 21st Century               [x]│
│ Subjects   14  │ Yuval Noah Harari · History, Anthropology         │
│ Publishers  9  │───────────────────────────────────────────────────│
│                │ The White Order                               [x]│
│                │ L. E. Modesitt, Jr. · Fantasy, Military           │
│                │───────────────────────────────────────────────────│
│                │ RECENT BOOKMARKS                                  │
│                │───────────────────────────────────────────────────│
│                │ [bk] The White Order      Part 14 · Line 1   [x]  │
│                │      "Powerful white mages killed..."             │
│────────────────│                                                   │
│ [@] Alice [lock]│                                                  │
└────────────────┴───────────────────────────────────────────────────┘
```

- **Left nav**: Recent and All books as the two primary views, each with a count; a Browse group below for Authors / Subjects / Publishers, each also with a count. Recent is the default landing view. Below the `lg` breakpoint there's no room for it beside the book list, so it collapses into a dropdown instead — toggled by the book icon alone (styled as a visible bordered button, its border tinted the brass accent, so it reads as tappable, unlike the plain "Skypiea" text beside it, which isn't part of the click target), closed by default, closing again on a selection, an outside click, or Escape, same as the Reader screen's dropdowns.
- **Account footer**: pinned to the bottom of the left nav (both the lg+ sidebar and the below-`lg` dropdown share this content) — a person icon and the signed-in `display_name` on the left, two icon-only buttons (border tinted the brass accent, same as the drawer toggle) on the right: Refresh, then Lock. For an admin session (credentials.md's "How a client knows its own role" — decoded from the session's own Turso token, not a database lookup), `display_name` is itself a link to Screen 4 (Manage); for a regular user it stays plain text, since there's nothing behind it to link to. This is the only place either action lives; there's no separate button for them in the top bar. Refresh re-loads metadata/access/bookmarks from Turso/R2 without a full re-unlock (for a book ingested/shared, or a bookmark/read-position added, from elsewhere since unlocking) — the search field disables for its duration, its border dimming to the same 65% opacity a disabled button's does (Bootstrap's own `.form-control:disabled` doesn't touch border opacity at all, unlike `.btn:disabled`, so this needed its own rule to actually look disabled instead of just as bold as ever). At lg+, the entire persistent left pane below the wordmark (nav items, account footer, Lock/Refresh included) and the content pane alike collapse into a single centered spinner while this runs, with the same two live-updating lines underneath it as Unlock's own spinner (a "Step N of 3" counter on top, then the current phase's label — "Loading your books" → "Loading your read progress" → "Loading your bookmarks" — beneath it, both falling back the same way before/after a phase is set); only the top bar survives untouched. Below lg, there's no persistent left pane to replace this way (it's a dropdown instead, off the top bar): clicking Refresh from inside it closes the dropdown right away and disables its drawer toggle (the book icon beside the wordmark) for the duration, consistent with the search box also disabling — so a refresh started from a phone always lands back on the plain top bar, not a stale open dropdown, and the drawer can't be reopened until it finishes.
- **Right pane, All books/Browse views**: one row per book, two lines each — title on top, then `Author · Subject, Subject · Publisher` underneath. In-progress books show "Part N" at the right edge (the Library screen doesn't fetch a total part count — see the Reader screen for that — so there's no fraction or progress bar here, and no "Finished" state either); unstarted books show nothing there.
- **Right pane, Recent view**: two stacked sections instead of a single list. "Continue Reading" is the book-row list above, most recently opened first — unlike the All books/Browse rows, it doesn't show a part number at all (this view is already scoped to "in progress", so it'd be redundant). "Recent Bookmarks" below it flattens every bookmark across every book, most recently created first, each row showing the book title, `Part N · Line M`, and a short preview of that line's text — clicking one opens the reader at that spot. Every row in both sections carries a small delete ("x") button that removes just that entry (forgetting a book's read position, or discarding a bookmark) without deleting the book itself. Each section sizes to its own content (capped at half the pane's height) rather than always splitting it evenly, and scrolls independently of the other, rather than one continuous page scroll through both.
- **Every list in the right pane renders virtualized** (windowed) — All books, browse-value, browse-entries (Authors/Subjects/Publishers), Continue Reading, and Recent Bookmarks alike, uniformly rather than only the ones large enough to need it today — so the screen stays responsive regardless of how large an account's library grows. Each list owns its own scroll region for this (rather than one shared ambient page scroll), which is why Recent's two sections scroll independently instead of as one continuous page.
- Top bar stays a slim strip above both panes: wordmark and a search field — no status pill; being on this screen at all already implies the vault is unlocked. At `lg`+, the wordmark sits in a fixed-width cell matching the sidebar's own width (border included), so the cell beside it lines up exactly with the right pane's content below; the search field itself is capped to half that cell's width there — but only once the viewport is wide enough for that half to comfortably fit the "Search your library" placeholder; below that (even at `lg`+, before the viewport is wide enough), it stays full width rather than cramping the placeholder into a box too narrow for it. Below `lg` proper, with no sidebar to align against, it just takes the full width of the space beside the wordmark toggle. Its border matches a bordered button's exactly at rest — same brass accent, same thickness — rather than a softer tint or thinner line of its own. Focusing it swaps in an even brighter brass accent (border and glow alike) instead of the stock blue browsers default to, with a narrower glow than usual so focus doesn't read as a thicker border.

## Screen 3 — Reader

A full-width reading pane with a part-navigation bar along the bottom. "About this book" and "Bookmarks" aren't a persistent side panel — each is its own dropdown, closed by default: Info hangs off the top bar (opens downward), Bookmarks off the bottom bar (opens upward, since it's anchored near the bottom of the screen).

```
┌────────────────────────────────────────────────────────────────────┐
│ [<]   The White Order                                          [i] │
│       L. E. Modesitt, Jr.                                          │
├────────────────────────────────────────────────────────────────────┤
│ PART 14 OF 41                                                      │
│                                                                    │
│ The White Order                                                    │
│                                                                    │
│ [bk] Powerful white mages killed Cerryl's father to protect their  │
│      control of the world's magic. Raised by his aunt and uncle,   │
│      Cerryl learns that he has inherited his father's magic        │
│      abilities...                                                  │
│                                                                    │
│ [bk] When Cerryl witnesses a white mage destroy a renegade         │
│      magician in the market square, he understands, all at once   │
│      and far too late, exactly what he is.                        │
├────────────────────────────────────────────────────────────────────┤
│ [<]  [14]/ 41  [>]                                            [bk] │
└────────────────────────────────────────────────────────────────────┘
```

- **Top bar**: an icon-only back-to-library button (no label), the current book's title/author, and the Info button (toggles its dropdown, closed by default; closes on an outside click or Escape). Below the `sm` breakpoint the author drops to its own second line instead of sharing one with the title — no room for both there. Left/right padding shrinks below `sm` too, giving a narrow screen back a bit more usable width.
- **Reading column**: comfortable line length, one part's text at a time — no chapter/whole-document view, always full width (there's no side panel competing for space). The book title and every line of body text render in Literata (a serif typeface designed for long-form reading), self-hosted rather than loaded from Google Fonts, in place of the rest of the app's default sans-serif system-font stack. The column's max-width is set in `ch` (character-width units, based on the current font), not a fixed pixel value, so a line stays around 70 characters long regardless of which font size is picked below — capped by the viewport's actual available width on a narrow screen, same as before. Each line has its own bookmark icon in the left gutter, only visible on hover/focus unless that line is already bookmarked (then it stays visible as a status indicator), filled in once bookmarked; clicking it again removes that bookmark, the same toggle either way. It scales with the font-size dropdown too, rather than staying a constant size while the text around it grows or shrinks. There's no separate "bookmark this part" control.
- **Info dropdown**: title, author, series if any, subject tags, and a short description pulled from the book's catalog metadata. A description longer than 200 characters shows truncated with an ellipsis and a "Show more"/"Show less" toggle rather than the full text up front. Below that curated summary, an "All metadata" section lists every other OPF/Calibre field the catalog entry carries — one row each — so nothing in the underlying record is hidden; omitted entirely for a book with no metadata beyond its filename. `description` and `subject` are left out of this section since they're already shown above with their own special-purpose rendering (sanitized/truncated HTML, subject badges) and would just be redundant as raw text; Calibre's own bookkeeping fields (`calibre:rating`, `calibre:title_sort`) are dropped outright since neither means anything to a reader. `calibre:timestamp`/`calibre:series`/`calibre:series_index` are relabeled `timestamp`/`series`/`series index`, and both `timestamp` and `date` are reformatted for a human reader ("January 15, 2020", or "January 15, 2020, 8:23 AM" if the timestamp actually carries a non-midnight time) instead of showing the raw ISO string.
- **Bottom bar**: a font-size dropdown (14/16/18/20/22/24px, defaulting to 18px on a full-size screen or 16px on a phone-sized one — same `sm` breakpoint as the bottom bar's own auto-hide below; same brass-themed border as Library's search field) sits at the far left, resizing the reading column's body text — a plain per-session preference, not persisted or saved anywhere. (The title heading doesn't resize with it — it's a Bootstrap heading sized in `rem`, relative to the page's root font size rather than the reading column's own, so it stays a consistent size regardless of the chosen body text size.) A vertical divider (spanning the bar's full height) separates it from the Previous/part-number/Next group, which stays tightly spaced internally — looser gaps everywhere else in the bar, tight within that one group. Previous/Next are icon-only chevrons with no visible button border (an unstyled brass-colored icon, not a bordered box — the only icon buttons in the app styled this way), flanking an editable part-number box (same themed border as the font-size dropdown; up to 3 digits — typing a number and pressing Enter or clicking away jumps there, clamped to the book's actual range) followed by `/ <total>`. No progress bar here. A second vertical divider, then the Bookmarks button sits at the far right of the bar on its own. Bookmarks lists entries most recent first by `created_at`, each showing which part and line plus a short preview of that line's text; clicking one jumps to that exact line (scrolling to it), not just its part. Each bookmark carries a small delete ("x") button that removes just that one, the same affordance as the Library's Recent Bookmarks rows. Below `sm`, the whole bar auto-hides on scrolling down the reading pane (more room for text on a phone) and reappears on scrolling back up, or on landing at the very top, or on switching part/book; at `sm`+ it's always shown regardless of scroll. While hidden, a round floating button (an up arrow) takes its place at the bottom-right corner of the screen, scrolling back to the top (and un-hiding the bar) when tapped — otherwise Bookmarks would be unreachable without manually scrolling back up.

## Screen 4 — Manage

Admin-only, reached by clicking `display_name` in Library's account footer (a plain link there, not a button, since it's just a route) — a regular-user session never sees it as a link at all. Whether a session is admin is decided once, client-side, by decoding its own Turso auth token's `perm` claim (`crypto/jwt.ts`'s `isAdminToken` — see credentials.md's "How a client knows its own role" and "Turso token scope"), not by looking anything up in the database; the route itself is guarded the same way (`RequireAdmin`, redirecting a non-admin straight back to `/library`), though the real enforcement is Turso's own token grants rejecting the write/schema verbs a regular user's token was never minted with, regardless of what this screen does or doesn't show.

Two panes, mirroring Library's own shell exactly rather than inventing a different layout for one more screen: the same top bar and the same lg+ persistent sidebar / below-`lg` dropdown split for the left nav, right down to the same account footer pinned to the bottom of the nav (person icon, display name, Refresh, Lock) — `display_name` is just never a link here, unlike Library's, since this screen already *is* where that link goes. The top bar's search field filters whichever section is currently selected — by name/id for Users, title/author for Books, txt title/recipient name or id for Shares. Unlike Library, the top bar carries a small back-arrow, always a link to `/library` (unlike the wordmark beside it, which stays plain here, same as Library's own) — at lg+ it sits centered over the sidebar's own box, and below lg it sits beside the drawer toggle instead — so going back to Library is always one tap away regardless of screen size or dropdown state, instead of a separate "← Library" row above Users/Books/Shares the way an earlier iteration had. Refresh reloads both the vault's own data and this screen's own Users/Shares lists, collapsing the whole sidebar-and-content region into one centered spinner while it runs, same as Library's own refresh. The nav's content otherwise differs from Library's, not its mechanics: Users/Books/Shares as the three sections (each with a count, same `NavItem` styling as Library's own Recent/All books/Browse). There's no heading repeating the section name above the list itself — the nav's own highlighted item and the search placeholder already say which section is active. Every text/number/password/select input in this screen's forms uses the same themed border as Library's search box, and the same `-sm` sizing as its buttons and the search box itself — every modal control in this screen is small-sized, not just the top bar's.

Each section is a select-a-row-then-act toolbar — Create/Edit/Delete, only whichever of those actually applies — rather than per-row buttons on every visible entry. The toolbar itself renders as one Bootstrap button group merged into the top bar's own search box (one seamless `.input-group`, same height and adjoining borders, not a separate row above the list), with each button's label collapsing to icon-only below the `sm` breakpoint. Every Create/Edit/Delete action opens the same kind of popup modal (a titled dialog, rounded corners and a fade/rise-in on open, centered over a dimmed backdrop, closed by its own small circular × button, an outside click, or Escape — hand-rolled the same way Library/Reader's dropdowns are, since this app has no Bootstrap JS to lean on for one), one labeled field stacked per row inside it, instead of each form inventing its own inline layout. Every modal renders at the same fixed, generously wide size regardless of which panel it's showing (a single confirm field looks just as roomy as the Create-user form), rather than each shrinking to its own content's width — and every text/select box inside a form stretches to that same full width too, rather than capping narrower than the modal around it. Users' and Shares' rows also carry a small leading icon (person/share) for the same consistency reason — Books reuses Library's own plain `BookRow`, which has none:

- **Users**: **Create** opens a form with just three fields — Turso database URL (prefilled from the admin's own session, editable), display name, and the shared regular-user Turso token to embed (see credentials.md) — `username`/`password`/`username_lookup_key`/`user_root_key` are no longer admin-typed at all; the form generates them itself (a 42-character `[0-9A-Za-z]` string for each of the first two, 32/256 random bytes respectively for the latter two — nothing about these ever needs to be memorable, since the only thing that ever "logs in" with them is Unlock's own Choose File flow reading them straight out of the downloaded JSON). Submitting ("Generate credentials") computes the full credential bundle and swaps the form for a read-only view of the generated JSON — pure client-side computation, nothing written to the database yet (see data/adminUsers.ts's `generateNewUser`/`persistNewUser` split) — alongside an **Edit**/**Copy**/**Download** button row and a checkbox ("I've saved this configuration (downloaded or copied)") that gates the real **Create user** button: disabled until checked. **Edit** re-opens the same three fields (prefilled) so the admin can fix a typo before persisting, via `updateGeneratedNewUser` — it only touches `downloadable`/`credsBlob`, leaving the already-generated username/password/keys untouched, and resets the "I've saved this"/"Copied!" state, since both described the JSON *before* the edit. Edit/Copy/Download all share the same plain, text-labeled, brass-bordered button style — no icons on any of the three. **Copy** copies the current JSON to the clipboard and shows a small "Copied to clipboard!" confirmation underneath the row for two seconds (reset on every click, not just the first, so copying twice in a row shows it twice). This is the one time the password and root key are ever shown, but unlike an earlier version of this flow, the modal stays freely closeable at this step — there's nothing to lose by backing out, since nothing's been created yet. Clicking the now-enabled **Create user** is the only step that ever touches the database: a spinner and progress text beside the button (same pattern as Books' Edit Save) track its two write phases ("Creating account…" / "Saving credentials…") before it reloads the Users list. Rows are one line: just the recovered display name (from `users.creds`, wrapped under the *admin's* own `umk` — see data_model.md — decrypted client-side; falls back to "Unnamed user" if it's `NULL` or undecryptable), no id shown (search still matches by id as well as by name, for picking a recipient elsewhere by number if that's all that's known). The admin's own row is the one exception `users.creds` can't cover — it's always `NULL` there — so this screen patches in the admin's own already-known `display_name` from the session instead of showing the fallback; that row also shows "(you)" and hides **Delete** entirely, since an admin can never delete themselves through this screen. **Edit** opens one panel with both things a user's account can be edited by the admin: reset password (a plain new-password field) and rotate root key (pastes in that user's *current* root key, which only the admin can supply from wherever they escrowed it — this can't work any other way, since the existing wrapped `umk` can only ever be decrypted with the key it was actually wrapped under; shows the new key once with a one-field download). **Delete** is gated behind typing the selected row's own id back before "Confirm delete" enables — this screen's only confirm-before-destructive-action pattern (everywhere else, e.g. Library's bookmark "x", deletes fire immediately).
- **Books**: the admin's own txt only (there's no "someone else's txt" case at all — see credentials.md, only the admin ever holds any), listed with the exact same `BookRow` Library's own book lists use (title, `Author · Subject, Subject · Publisher`, "Part N" for an in-progress book) — reusing Library's own `useLibraryBooks`/`allBooksSorted`/`matchesSearch`, so this list looks and searches exactly like Library's "All books" view, not a separate approximation of it. No **Create** here — that stays a `--txt-ingest`-only operation, since it needs the real file-upload/OPF-parsing pipeline this screen doesn't reimplement. **Edit** opens a curated-fields metadata form (title/author/publisher/subjects/description) and writes it straight back to R2. **Delete** uses the same type-the-id-to-confirm pattern as Users, and is a full delete — R2 parts, Turso rows, and the `txt_metadata` entry all actually removed (see credentials.md's "The admin role can get real R2 write access" section), not a Turso-only stand-in.
- **Shares**: existing grants on the admin's own txt, each row (`ShareRow`) showing the shared txt's title on top and, underneath it, the recipient's display name and numeric id — same two-line shape as Books' own rows, rather than one truncated line. **Create** opens a form to grant a new one: pick one of the admin's own txt, then pick a recipient from a dropdown of every *other* account's display name/id (the same Users list ManageScreen already loads for the Users section — one shared cache, not a second fetch of its own; the admin's own account is excluded, since only the admin ever owns/shares txt at all, and sharing with themselves would be meaningless) — needs nothing secret from the recipient, only their already-public `key_store.pub_key`. **Delete** opens a lightweight confirm panel (title, recipient, Cancel/Revoke share buttons) rather than firing immediately — simpler than Users/Books' type-the-id `ConfirmDeleteField` (a share is still easy to re-grant, unlike an account or a txt, so it doesn't need that heavier gate), but still an explicit confirmation before anything's revoked.
